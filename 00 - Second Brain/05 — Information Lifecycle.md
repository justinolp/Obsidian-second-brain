# Information Lifecycle

## Pipeline

`Input → Candidate → Atomic → Classified → Linked → Verified → Canonical → Used → Learned → Revised / Deprecated`

## Capture
Anything potentially useful enters as a candidate. Do not prematurely treat raw input as truth.

## Atomization
Break information into the smallest useful reusable knowledge units. One note should have one dominant purpose.

## Classification
Use type, domain, status, source, confidence, date and relationships where they materially improve retrieval or governance.

## Linking
Link related concepts, projects, decisions, research, systems and evidence. Semantic links are not the same thing as MOCs or index pages.

## Canonicalization
Only verified and stable information becomes canonical system knowledge. Conflicting information is preserved as uncertainty until resolved.

## Deprecation
Superseded knowledge stays traceable. Mark it `deprecated` or `superseded` and link the replacement.

## Provenance
Important facts should preserve source, date, method and verification status.
