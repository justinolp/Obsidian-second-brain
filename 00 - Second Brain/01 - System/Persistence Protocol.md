# Persistence Protocol

## Persist when
- a system rule changes
- a decision is made
- durable knowledge is created or corrected
- a research result materially affects the system
- a learning changes future behavior
- an error produces an actionable improvement
- an important project state changes

## Procedure
1. Identify information atoms.
2. Classify each atom.
3. Identify authority.
4. Create or update the canonical note.
5. Link related notes.
6. Record provenance and verification state.
7. Read back when possible.
8. Run regression checks for system-impacting changes.

## Principle
Persistence is not complete merely because a file was written. The stored state must be coherent, linked and appropriately verified.
