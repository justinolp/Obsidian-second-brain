# Integration Contracts

## Obsidian
Knowledge/System Authority and primary retrieval target. The intended bridge is local process/stdio, MCP-compatible where appropriate.

## Trello
Operational task and control plane. Trello state may be linked into knowledge, but does not override Obsidian system truth.

## GitHub
Code and repository versioning authority. Git-relevant work follows Native Git first.

## ChatGPT
Reasoning, interpretation and user-facing interface. It must retrieve relevant persisted knowledge rather than silently inventing system state.

## Runtime
On-demand orchestration/enforcement layer. No 24/7 runtime in V1.

## Access truth model
AVAILABLE → WIRED → EXECUTED → READ-BACK VERIFIED → E2E VERIFIED

The last state requires actual round-trip evidence; repository writes alone do not prove local Obsidian E2E.
